# Template Architect

Authoritative framework for architecting, scaffolding, and optimizing bare-bones structural application templates and clean UI wireframes across BEHTML, semantic HTML/CSS, and Python application runtimes. Enforces the 6-tier layered architecture, zero filler content, strictly functional placeholders, invisible architectural execution, and blank canvas delivery.

## Summary

Acts as the foundational template generator and layout scaffold architect across both frontend UI containers and backend executable templates. Eliminates AI-generated filler, lorem ipsum, decorative narratives, and framework meta-commentary. Embeds Elton Boehnen's canonical Release_Version 300 templates (Python Core/Validator and HTML Core/Validator) and guarantees that all spatial grids, 8-lane bounds, and responsive containers execute silently in code while presenting minimal, literal placeholder tags ("Page Title", "Body Paragraph text", "Sidebar link1", "topnav").

## When to Use

- Architecting empty application layouts or page templates across BEHTML, HTML5, or Flask web apps.
- Scaffolding bare-bones UI wireframes, dashboards, split-pane editors, and content grids.
- Generating canonical executable starter templates in Python or HTML embedding BEJSON Core and Validator routines.
- Establishing spatially locked layout frameworks before domain content is authored.
- Enforcing zero-filler, blank-canvas discipline across frontend generation workflows.

## When NOT to Use

- Populating templates with real domain content, copy, or business logic (handled by domain services).
- Tracing and extracting navigation sitemaps from existing websites (use `ui-navigation-decomposer`).
- Validating raw BEJSON 104/104a tabular records (use `bejson-schema-validator`).
- Generating 25-50 point feature brainstorm lists (use `ideation-feature-composer`).
- Refactoring application persistence models or server logic (use `bejson-codebase-refactor`).

## Layer Optimization & Ecosystem Integration

`template-architect` bridges presentation, scaffolding, and substrate contracts across the 6-tier hierarchy:

- **Layer 1 (Core Substrate Integration)**: Embeds Release_Version 300 Core error codes (1-29) and primitives (`bejson_core_load_file`, `bejson_core_atomic_write`, `bejson_core_get_field_map`) in executable templates (`assets/BEJSON_Template_PY_Full-v1.py`, `assets/BEJSON_Template_HTML_Full-v1.html`).
- **Layer 2 (Domain Engine / Validator Integration)**: Directly embeds or targets `bejson-schema-validator` routines (`validate_bejson`, `bejson_validator_validate_string`, `bejson_validator_get_report`) in validator templates.
- **Layer 3 (Automation & Scaffolding Synergy)**: Complements language scaffolders (`bejson-scaffold-python`, `bejson-scaffold-javascript`, `bejson-scaffold-bash`) by providing standardized layout shells that background scripts and web servers render.
- **Layer 4 (UI & Presentation Root)**: Sits as the structural layout authority alongside `behtml-spatial-builder` (which handles mathematical 8-lane BEHTMLElement serialization) and `ui-navigation-decomposer` (which maps sitemaps).
- **Layer 5 (Architecture Pre-Planning Handoff)**: Consumed by `mfdb-*-planner` when architecting frontend views, admin dashboards, and publisher skeletons.

## The 5 Core Invariant Laws of Template Scaffolding

Every template generated by this skill must strictly conform to these five foundational laws:

### Law 1: Zero Filler Content
Templates are structural skeletons, not finished brochures. Never populate layout containers with:
- Lorem ipsum, simulated Latin text, or generic copywriting.
- Fictional bios, fake testimonials, mock product cards, or synthetic news feeds.
- Decorative placeholder images or unrequested stock graphics.
- Fabricated marketing claims or placeholder metrics ("100K Users", "$1.2M ARR").

### Law 2: Strictly Functional Placeholders
Define boundaries using minimal, literal, title-cased labels that convey spatial and structural intent:
- Permitted text placeholders: `"Page Title"`, `"Subtitle"`, `"Body Paragraph text"`, `"Section Heading"`.
- Permitted navigation placeholders: `"topnav"`, `"nav_link_1"`, `"nav_link_2"`, `"Sidebar link1"`, `"footer_link"`.
- Permitted control placeholders: `"Submit"`, `"Cancel"`, `"Action Button"`, `"Input Field"`.
- Banned text placeholders: Multi-sentence descriptive guidance, instructional paragraphs, or advice on what the user should write.

### Law 3: Invisible Architecture
Execute layout logic, grid coordinates, and framework mechanics silently in the code:
- Never render visible phrases like `"grid space activated"`, `"lane 0 to 7 active"`, `"container wrapper rendered"`, or `"breakpoint triggered"`.
- Keep BEHTML coordinate math (`x_start`, `x_span`, `y_start`, `Ry=32px`) and CSS Grid definitions contained entirely in markup attributes, styles, and data structures.
- The rendered page must appear completely blank except for structural boxes and functional tags.

### Law 4: Blank Canvas Rule
The template canvas belongs entirely to the user:
- Deliver an uncluttered workspace ready for immediate implementation.
- If a section, sidebar, or panel was not explicitly requested in the prompt, leave it out or leave it completely blank.
- Never force the user to manually select and delete unrequested AI elements.

### Law 5: Direct Delivery
Deliver the raw artifact directly without conversational baggage:
- Output the clean template code immediately.
- Do not prepend greetings, conversational preambles ("Here is your template:"), or apologies.
- Do not append postscript explanations detailing how the CSS grid functions or why specific classes were selected.

## Step-by-Step Template Authoring Workflow

1. **Identify Required Spatial Regions**:
   - Parse the requested layout into discrete zones (Header, Navigation, Sidebar, Content, Footer).
   - Reject unrequested zones to honor the Blank Canvas Rule.

2. **Select Target Architecture & Framework**:
   - If BEHTML: assign 8-lane X coordinates, quantized 32px Y coordinates, and layer IDs.
   - If HTML/CSS: configure flexbox or grid containers with high-contrast structural borders using the Tri-Color palette.
   - If Executable Backend Template: copy the appropriate Python or HTML template from `assets/` and populate header metadata.

3. **Insert Strictly Functional Placeholders**:
   - Replace every text block with literal spatial tags.
   - Ban lorem ipsum, multi-sentence filler, and descriptive advice.

4. **Verify Invisible Architecture & Zero Fluff**:
   - Run the bundled fluff linter:
     ```bash
     python3 skills/template-architect/scripts/scaffold_fluff_linter.py <template-file>
     ```

5. **Direct Delivery**:
   - Output the code artifact immediately with zero conversational framing.

## Gotchas & Anti-Patterns to Avoid

- **The Helpful Explainer**: Inserting text like "Put your company mission here in 3-4 sentences" violates Law 2. Use `"Body Paragraph text"`.
- **The Decorative Filler**: Adding mock cards, fake avatars, or sample blog posts violates Law 1. Leave containers empty.
- **Framework Bragging**: Displaying grid lane indicators or status badges in the rendered DOM violates Law 3. Keep layout math internal.
- **Overwriting Bundled Primitives**: In Python or HTML templates, never alter the embedded Core/Validator function bodies; build new logic around them.
