## 1. Summary & Core Mission

`goal-roadmap-composer` transforms high-level Goal Contracts into granular, turn-by-turn execution roadmaps. Standard LLMs suffer from cognitive degradation when attempting to solve multi-step problems in a single sweeping generation.

This skill enforces the **1-Action-per-Task Law**:
Every milestone is decomposed into small, self-contained, verifiable tasks formatted as interactive markdown checklists:
- Exactly ONE functional transformation per checklist item.
- Explicit verification criteria after every step.
- Rollback safety checkpoints before modifying persistent state.

---

## 2. Standard Roadmap Template

Roadmaps generated by this skill follow a standardized, high-density format written to `dev/roadmap.md` or displayed in the conversation:

```markdown
# Goal Execution Roadmap: [Objective Title]

> **Goal Contract**: `dev/goal_contract.104a.bejson`
> **Target Files**: `src/main.py`, `tests/test_main.py`
> **Negative Boundaries**: Zero modifications to `$ADMIN_LIBRARIES`

## Phase 1: Environment & Pre-Flight Verification
- [ ] 1.1 Run baseline unit tests to establish green status.
  - *Verify*: `python3 -m unittest discover tests` (Exit Code 0).

## Phase 2: Core Implementation (1-Action Steps)
- [ ] 2.1 Scaffold data structures in `src/models.py`.
  - *Verify*: Syntax check `python3 -m py_compile src/models.py`.
- [ ] 2.2 Implement service logic in `src/service.py`.
  - *Verify*: Import check `python3 -c "import src.service"`.
- [ ] 2.3 Wire CLI flags into `src/main.py`.
  - *Verify*: Execution check `python3 src/main.py --help`.

## Phase 3: Quality Gates & Finalization
- [ ] 3.1 Execute complete regression test suite.
  - *Verify*: `python3 -m pytest tests`.
- [ ] 3.2 Audit touched files via `goal-drift-auditor`.
  - *Verify*: Zero drift violations reported.
```

---

## 3. The Three Decomposition Invariants

1. **Granularity Ceiling**: No checklist item may require touching more than two files simultaneously. If a step requires touching three or more files, it must be split into sub-steps.
2. **Explicit Verification Command**: Every item must state the exact shell or tool command used to prove that the item passed.
3. **Sequential State Dependency**: Tasks are ordered so that prerequisites are strictly completed before downstream steps begin.

---

## 4. Execution & Containment Contract (Level 3 Guardrail)

When invoking subagents to compose roadmaps, always mandate `--sandbox` containment and deterministic exit codes (`0` = OK, `10` = Path Failure, `20` = Env Failure, `30` = Schema/Validation Failure):

```bash
agy --sandbox -p "Compose execution roadmap for goal contract using goal-roadmap-composer."
```

## When NOT to Use

Do NOT use `goal-roadmap-composer` for out-of-scope tasks. Route immediately to the designated sibling skill:

- **Formalizing initial goal contracts and negative boundaries**: Redirect immediately to `goal-contract-architect`.
- **Auditing execution drift and enforcing user override halts**: Redirect immediately to `goal-drift-auditor`.
- **Executing sequential single-task JobMaker workflow runs**: Redirect immediately to `job-workflow-manager`.
- **Brainstorming 25-50 point product feature menus**: Redirect immediately to `ideation-feature-composer`.
